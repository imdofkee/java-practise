## Подготовка

1. Локально поднять на компьютере базу данных с помощью docker compose. Пример того как это делать можно найти в этом репозитории в /test-database. + добавить используемый docker compose файл в ваш репозиторий.
Работа выполняется в том же личном монорепозитории (отдельный второй модуль) студента, что и 1 лабораторная.
Задание
Каждый студент получает некоторую сущность (вариант 29  - файл), состоящую из нескольких полей.
Необходимо разработать небольшое Java-приложение, которое:

1) Подключается к БД
   Подключение выполняется при запуске программы через JDBC-драйвер, используя url для подключения и параметры доступа.
   Опционально за дополнительные баллы: использование connection pool hikaricp.
2) Создает таблицу для сущности
   При запуске программы необходимо проверить наличие таблицы и, в случае отсутствия, создать таблицу.
   Это необходимо для корректного перезапуска.
   Название таблицы соответствует сущности, например book, student и т.д.
   Опционально за дополнительные баллы: используйте liquibase для создания таблицы и контроля
3) Реализует класс-репозиторий для CRUD-операций
   Необходимо реализовать отдельный класс-репозиторий, который полностью инкапсулирует работу с базой данных.
   Репозиторий не должен «засорять» бизнес-логику SQL-запросами.
   То есть вся работа с jdbc выполняется в этом классе.
   Опционально (в качестве упрощения, без дополнительных баллов): использование jdbi вместо чистого jdbc.
   Репозиторий должен реализовывать интерфейс (вместо слова entity используйте свою сущность, например: PersonRepository, PersonEntity):
   public interface EntityRepository {
   // Create (возвращает id созданной записи)
   int save(Entity entity);

   // Read (возвращает null, если запись не найдена)
   Entity findById(int id);

   // Read по второму параметру сущности из вашего варианта
   Entity findByField(String field);

   List<Entity> findAll();

   // Update (используйте id для поиска сущности, возвращайте false, если запись не найдена)
   boolean update(Entity entity);

   // Delete
   void deleteById(int id);
   }
   Все методы кроме save должны быть идемпотентными! То есть при многократном повторном вызове возвращать один и тот же результат.
   Класс Entity представляет собой вашу сущность, например:
   public class PersonEntity {

   private final Integer id = null;

   private String title;

   private Integer age;
   }

4) Демонстрирует в Main выполнение операций
   Необходимо вызвать в методе main все методы репозитория, для демонстрации корректной работы программы.
   Обратите внимание, не нужно реализовывать в Main полноценный TUI с выбором действий, вводом с консоли и тд.
   Требуется просто позвать в main методы репозитория, для демонстрации их корректной работы. Не усложняйте себе жизнь.
   Правила оценивания

10 баллов — базовое выполнение работы, ответы на вопросы по коду
5 баллов — использование connection pool hikaricp
5 баллов — использование liquibase

Итого вы можете получить до 20 баллов.
Формат сдачи
Решение требуется прикрепить к соответствующему заданию гугл класса в виде ссылки на git-репозиторий.
Посмотрите перед сдачей популярные ошибки 2 лабораторной чтобы сразу их избежать!
Работа в обязательном порядке защищается в очном режиме!
